# Voice Memo Mode

For solo recordings, casual conversations, brain dumps. The output is for the user's private use - processing, reflection, tracking thought patterns over time.

This mode is structurally lighter than the others. Less template, more preservation of voice.

## Template

```markdown
# {Context} - {Date}
**Format:** {Solo voice memo / casual conversation with [name]}
**Duration:** {if known}

---

## What this was about

{One paragraph framing what the user was processing. Not a summary - a starting point.}

---

## Themes that came up

### {Theme 1 - name it in the user's own framing}
{Cleaned narrative. Preserve emotional texture, not just facts.}

### {Theme 2}
{...}

### {Theme 3}
{...}

---

## What's spinning

{The unresolved stuff. Loops the user is in. Things they returned to multiple times in the memo. Important to surface because returning-to is signal.}

- {Loop 1}
- {Loop 2}

---

## Realizations / shifts

{Moments in the memo where the user said something that sounded like a realization - even a small one. Preserve with light editing.}

- {Realization 1}
- {Realization 2}

---

## Decisions or intentions stated

{If the user said "I'm going to" or "I want to" or "I'm done with X" - capture it.}

- {Decision/intention 1}
- {Decision/intention 2}

---

## Open questions to revisit

{Things they asked themselves but didn't answer. These are markers for future sessions.}

- {Question 1}
- {Question 2}

---

## If a coach or mentor is in the recording

{Capture their reflections, reframes, or questions separately. Don't merge with the user's voice.}

- {They said: ...}
- {They asked: ...}
```

## Mode-specific rules

- **Light cleaning, not summarization.** This is processing material. Cut filler ("um," "like," "you know") but preserve the texture of how the user talks to themselves or in casual settings. Run-on sentences are okay if they carry tone. Tangents that contain something real stay in.
- **Don't impose structure where there isn't any.** If a memo is genuinely scattered, the notes should reflect that. Group by theme where themes exist, but don't invent themes to make the output look organized.
- **Preserve emotional language.** "I felt frozen again" stays. "I'm so over this" stays. Cleaning emotional language into neutral phrasing strips the data.
- **Returning-to is signal.** If the user circled back to the same topic three times in a memo, that's important. Note it in "What's spinning" even if they didn't resolve it.
- **No interpretation.** Voice memos are raw material for *the user* to interpret. If they said something ambiguous, capture the ambiguity. Don't translate "I don't know why I do this" into "the user struggles with X pattern" - that's a separate job, not transcript processing.
- **The file is the user's record.** Another person's quotes go in their own section but the framing is always "what the user is processing."
- **Casual conversations.** If the recording is a conversation with one other person (a friend, family member), capture both voices. Note who said what. The "themes" section is still organized around what the user is processing - not a balanced two-sided summary.

## When the memo is really a thinking session

If the memo is clearly the user trying to decode a thought pattern or a stuck point, say so at the end in one line and offer to work through it separately. Don't start that work unasked.

## Naming

For solo memos: `Voice_Memo_{Date}.md` or `Voice_Memo_{Topic}_{Date}.md` if a clear topic emerged.

For casual conversations: `Conversation_{Other_Person}_{Date}.md`

Examples:
- `Voice_Memo_May11.md`
- `Voice_Memo_PostPitch_Apr24.md`
- `Conversation_Mom_May05.md`

If the topic is sensitive or personal, default to a generic name and let the user specify if they want more.
