# Class / Lecture Mode

For lectures, class sessions, guest speakers, course discussions. Single primary speaker (professor or guest), audience of students.

Gold standard: `/mnt/project/BizChallenge_Class2_Session_Notes.md`, `Fintech_Class1_Session_Notes.md` style.

## Template

```markdown
# {Course Code} {Course Name} - Class Session {N}
**Speaker:** {Professor name / guest name + title}
**Institution:** {school or organization / location}
**Topic:** {As stated by speaker or course catalog}
**Format:** Lecture + discussion + Q&A / case discussion / off-site visit / etc.
**Transcripts processed:** {note if part 1 / part 2 / full session}

---

## 1. {First major section - usually housekeeping or course logistics if covered}

{Cleaned content. Preserve professor's specific phrasings as quotes.}

---

## 2. {Next major conceptual block}

**{Sub-theme or key claim}**

{Cleaned narrative. Bullet structure when listing.}

**Key reframe / counterintuitive claim from {Professor}:**
- {Direct quote or close paraphrase}
- {Why it matters / what it inverts}

**Counterexample raised:**
- {Speaker's counterexample preserved with substance, not just label}

---

## 3. {Continue by conceptual section, not chronologically}

...

---

## Unresolved questions / cliffhangers

{Things the professor explicitly left open. Things that point to next session.}

- {Question or open thread #1}
- {Question or open thread #2}

---

## Items referenced for follow-up

{Pre-reads not yet discussed, slides he skipped, links he gave.}

---

## Attribution questions

{Only if unclear speaker moments. Usually one main speaker in this mode, so often empty.}
```

## Mode-specific rules

- **Organize by concept, not chronology.** If the professor circled back to a topic 30 minutes later, merge it into the same section. The reader wants the structure of the ideas, not the order of utterance.
- **Preserve specific framings as quotes.** When a professor inverts something, names something, or uses a specific phrase ("TechFin not FinTech," "compliance ceiling," "panopticon model"), quote it verbatim. These are anchors the user will cite later.
- **Counterexamples are gold.** When a professor raises a counterexample to make a point, preserve both sides - the original claim and the counterexample. Don't collapse them.
- **Cliffhangers matter.** Professors often signal next session's direction at the end. Always include an "Unresolved questions / cliffhangers" section.
- **Slide mismatch.** If reference slides are attached and they don't match what the professor said, the professor wins. Note the gap if it changes meaning.
- **Guest speakers.** Track who's saying what. Guest's name in the header. Quotes attributed to guest, not generic "the speaker."

## Naming

`{Course_Code}_Class{N}_Session_Notes.md`

Examples:
- `Fintech_Class2_Session_Notes.md`
- `Strategy_Class6_Session_Notes.md`
- `Operations_Class3_Session_Notes.md`

If the user has been using a specific naming pattern in the project (`BizChallenge_Class2_Session_Notes.md`), match it.
